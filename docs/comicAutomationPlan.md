# 漫画简化流程与自动化实施步骤

更新：2026-10-28。

## 用户主流程

五个区域：灵感与脚本 → 角色与画风 → 分镜与出图 → 字幕与排版 → 审稿与导出。原有八个详细步骤保留在所属区域内，用户可以精修，但默认不需要逐一操作。

最少参与：填写剧情或方向，选择本期角色与形态，然后点击“一键制作草稿”；系统补齐内容到待审稿，用户检查后导出。事实来源未核对、角色匹配有歧义、重画候选未决定时停下来说明原因，不替用户猜测。

## 第一阶段：页面内辅助制作

本轮实现的入口按已有业务函数串联，不另建一套生成服务。

1. 检查本期选题、文字与图片服务是否可用。
2. 复用本期已绑定画风；没有时复用默认画风，再没有时使用已有日漫预设。模型娘可选择已分析的Q版或成人版画风。
3. 没有分镜时生成脚本与分镜，有分镜时保留；不自动重写用户稿件。
4. 仅生成本期出场角色缺失的正式图，优先使用本期画风。
5. 逐格生成缺失图片，每次完成后保存。已生成但设定失效的图片、未采用候选先交给用户处理，不整集自动重画。
6. 整理对白、保留已有气泡编辑和心声；首次出图使用画外留白以减少遮挡及重叠。
7. 生成成品预览，停在待审稿；人工确认后才能导出。

可以要求在当前步骤完成后暂停。页面需要保持打开，关闭页面不会继续运行；失败不会自动重新请求模型。已有的图片与项目文件构成可继续制作的进度，但这不是可在系统重启后自行恢复的后台任务队列。

## 第二阶段：持久运行记录与恢复

先实现任务执行，再增加每天触发，避免“有定时按钮但实际无法恢复”。任务固定projectDirectory、episodeId、角色ID与形态、styleId、文字及生图服务、每次最多出图请求数。

状态：queued → preparing → planning → characters → drawing → lettering → reviewReady；中途可以paused、failed或needsAttention。

每一步保存：runId、stepId、输入指纹、状态、开始/结束时间、图片路径、请求数、错误类型。锁以工作区和作品为单位，跨前台/后台只能有一个写入者；文件快照仍使用现有revision冲突检查和原子写入。

每张图先写请求记录再发起请求；收到并校验图片后立即保存输出路径和指纹。若调用超时但远端状态未知，进入needsAttention，先检查本次会话是否已有输出，不自动重复发起可能再次扣费的请求。429、认证失败、网络中断、超时分别记录，不无限重试。

启动恢复：只加载已有运行记录；正在执行而没有明确结果的步骤先标记needsAttention。只有确认未发出请求或确认失败、可安全重试时才能继续。已成功格不重画；角色、画风或分镜输入变化后重新计算指纹，并明确列出需更新的格。

成本限制优先采用可观测的出图请求数。当前CLI没有逐图美元账单，不能伪造实际USD；将估算与实际用量分开，设置本次最多新增图片数，达到上限即暂停。

## 第三阶段：定时任务

持久任务记录包含名称、启用状态、Asia/Shanghai时区、每日或每周触发、nextRunAt、上次runId。任务执行在独立runner中，HTTP请求和浏览器不承担长时间调度。

用taskId＋计划触发时刻构成唯一运行键，同一计划不重复创建一期。错过触发时间默认标记待补跑，不在启动时连续补跑所有历史日期。每次任务默认新建一期并冻结角色及画风快照；失败继续该期，不另建重复作品。

默认终点为reviewReady。审稿、对比候选、最终导出和平台发布仍保留明确的人为决定。定时任务创建后必须显示下一次运行时间和实际运行记录，不能只保存表单就显示“已运行”。

## 验证边界

第一阶段可以通过实际页面进行小批量验证。第二、三阶段仍是实施方案，本轮不显示为已启用的后台日更服务；也没有替用户创建每天自动消耗额度的计划。
