# 换电脑试用与打包前基线

日期：2026-10-26。本版本是功能与问题均可追踪的开发快照，不是成品画质或Windows安装包已验收的发行版。

## 画质问题在哪里

1. 先前三次本地验证为384×512草稿。但本轮查看用户最新图片后，确认 `fluxKleine4be1cf25be1404299edf7f676057908.png` 已为896×1152，奔跑角色仍有三条腿；另两张新分格为768×1024。因此当前畸形不能简单解释为草稿分辨率，提高画质档位已不足以解决问题。正常制作应在模型合适的分辨率下单格验证，再排版导出。
2. 当前klein为4B、4bit蒸馏模型，不等于最高质量动漫模型。4步是该蒸馏模型的正常用法，不应把步数加到几十或几百就认为质量会提升。量化和低分辨率会带来质量取舍，但未做相同输入的高精度对照，不能认定4bit就是肢体畸形的根因。
3. 用户目标是自然动漫比例的生活四格。之前角色资产混合Q版与多视图；本轮用户已生成新的768×1024角色图，但原始参考与历史结果仍在。资产是否符合新画风要分别核对，不能仅用旧Q版状态解释新图片问题。
4. 已修复画风遗漏、旧角色画风覆盖全篇、默认站位/构图过强等问题。模型是否正确执行新动作、新镜头及衣物细节，尚未验收。
5. 当前本地多参考是软图像条件，没有分区身份约束、姿态/骨架控制、局部肢体修复，也没有自动视觉解剖验收。因此三条腿等结果应直接判为废图，不能当作可发布成品。提示词长度、参考干扰和模型能力各自可能影响结果，尚无严格对照把某一项认定为该张畸形的唯一原因。

优先顺序：统一角色资产与画风→单格适当分辨率→明确角色/道具归属→复杂动作使用经验证的姿态/分区工作流→局部修复→人工验收。先验证一个有明确肢体动作的双人镜头，不重画整集。不把增加锐化/放大当作解剖修复。

## RTX 5060 判断

- 普通桌面RTX 5060为8GB显存；5060 Ti有8GB/16GB版本，不能混淆。以目标电脑实际显存为准。[NVIDIA规格](https://www.nvidia.com/en-us/geforce/graphics-cards/50-series/rtx-5060-family/)。
- 换显卡不等于更换模型的绘画能力。同模型/同语义输入仍可能生成多余肢体；跨MLX/CUDA结果也不保证逐像素一致。更好的硬件/推理生态可使更合适的模型、精度、分辨率和控制工作流更可用，改善需要实际对照，而不是仅换卡。
- 本项目自带的MLX Z-Image/klein入口明确仅macOS Apple Silicon可用，不能将这个Python环境复制到Windows使用。Windows/NVIDIA建议另装ComfyUI，通过软件已有“本地ComfyUI”供应商连接。[ComfyUI Windows便携版](https://docs.comfy.org/installation/comfyui_portable_windows)。
- klein4B官方原始配置的约13GB VRAM描述，不是8GB 5060可原样加载的保证。量化与卸载需要另选兼容权重与工作流，参考图数量和分辨率也影响内存。本项目未在5060测过速度、峰值或画质。[BFL模型卡](https://huggingface.co/black-forest-labs/FLUX.2-klein-4B)。
- ComfyUI供应商已经存在，但尚无打包附送、经过双人物身份和肢体验收的默认工作流。换电脑后需先在ComfyUI独立跑通，再导出API格式JSON，配置正向文本、尺寸及按顺序的LoadImage节点。现有适配器固定输出768×1024；不能把官方随便一个工作流当作即插即用。API配置可用性也不等于实际生图能力通过。

## 备份边界

GitHub仅保存代码、字体/公共静态资源与说明。`data/`、`node_modules/`、`build/`、本地Python环境、模型缓存、API密钥、平台Cookie和浏览器登录资料均不随仓库提交。

本地另外提供 `outputs/comicWorkspaceBackup.zip`，仅包含各空间的comicProject.json与assets图片。包含当前图片、候选和历史版本，故不会丢失创作进度；不包含settings.json、comicJobs、localServices或账号/浏览器资料。该压缩包仅留在本机，未上传GitHub。解压到新电脑仓库根目录后会恢复 `data/workspaces/<空间ID>/...`。在空白安装中恢复，不覆盖新电脑已有同名空间；迁移前保留原目录副本。

素材库新增“未被引用/仅历史/当前或设定使用中”筛选；可将筛选出的未引用图片批量移入回收站并恢复。仍在角色、画风、候选或历史中的文件继续保护。该操作仅修改回收标记，不删除文件、不释放空间。历史版本解除引用/归档及物理清理尚未实现，不宣称有一键彻底清理能力。生成任务中还留有图片副本，后续需单独提供可恢复的任务缓存清理。

## Windows源码启动

安装Git及Bun（仓库packageManager指定1.3.14），使用备份快照对应提交。

```powershell
git clone https://github.com/yunmengze-lzq/xiaolengcomicStudio.git
cd xiaolengcomicStudio
bun install --frozen-lockfile
bun run --cwd apps/web build
bun run --cwd apps/server build
$env:TOONFLOW_SERVER_HOST="127.0.0.1"
$env:TOONFLOW_SERVER_PORT="3187"
bun build/server/index.js
```

浏览器打开 `http://127.0.0.1:3187/#/comicStudio`。这是源码运行指引，尚未在Windows执行验证。macOS的`startComic.command`不可作为Windows启动器。

新电脑需自行配置文本/生图服务，重新本人登录采集平台。Codex入口也依赖该电脑独立安装、登录和可用模型，不能沿用作者环境。先确认界面能启动和空间能恢复，再检测文本模型；最后单独验证ComfyUI的单人、双人参考、肢体动作、候选保存与导出，不连续批量出图。

## 安装包前的门槛

- Windows干净环境源码启动与项目恢复实测。
- 确定一个兼容8GB显存、参考/姿态能力明确的默认工作流，记录模型许可证与版本；用同一素材做一次针对性画质验收。
- 模型路径、运行时、数据目录与账号设置独立管理；安装包不携带作者模型缓存、账号或绝对路径。
- 完成角色与成品质量验收、废图归档恢复、升级/回滚和依赖授权清单后，才构建目标平台安装包并在无开发环境机器验证。当前仓库存在桌面打包脚本，不等于本次已经产出可用安装包。
