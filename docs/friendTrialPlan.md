# 小冷漫画：作者测试与朋友试用计划

更新：2026-10-25。当前阶段：先保留源码版本，由作者继续测试；未发布安装包、未开放公网、未开始邀请朋友。

## 本轮交付

- 发布正文保留编辑能力，新增五种文案风格和按需生成候选；采用候选才替换正文。
- AI 辅助说明、参考来源移到发布前自审区，默认不附加到正文；可以单独勾选加入。
- 发布包的 `publish.txt` 只保留最终文案，来源和创作说明另存 `internalReview.txt`；作品 JSON 与素材来源档案保留。
- 兼容旧版自动生成的固定说明文案：只清理完全匹配旧模板的内容，不清理用户手写的其他正文。

## 阶段一：作者继续测试（最高优先级）

| 任务 | 通过条件 | 当前边界 |
| --- | --- | --- |
| 发布文案 | 五种风格可选择；候选可编辑、采用或放弃；保存重载不丢；导出只带勾选的附加信息 | 本轮按需调用接口已实现；不自动消耗模型额度做回归 |
| 单格重画 | 旧图保留，新图成为候选；采用、拒绝、保存重载均正确 | 历史对比已操作；新增候选完整推理链仍待一次受控验证 |
| 动作与角色 | “猫叼袜子、一人一猫”正确；连续两格身份稳定 | 提示词约束已保存，实际画质纠错尚未确认；本地普通图生图不能承诺身份锁定 |
| 模型设置 | 文本/图片分开配置；第三方与本地服务的错误提示清楚，失败不丢数据 | 已有部分服务真实通路；每个供应商不视为都已验收 |
| 导出 | 中文气泡、位置、分格、文字和图片一致；审稿失效机制正确 | 已有真实导出结果，后续修改要继续回归 |

验证以一条最短路径为单位：先无调用的界面与保存检查，再在作者控制下做必要的一次文本或单格图片请求；不默认连续生成整篇作品。记录模型、耗时、错误和结果，不把构建通过当作功能通过。

## 阶段二：朋友本地试用前

1. 在一台没有作者环境的新设备上验收：克隆、安装、构建、启动、创建首个项目、配置一个文本模型和一个图片模型。补充平台、依赖及硬件要求。
2. 整理统一新手入口：清楚说明当前模型、是否付费、输出去向；完善首次设置、空状态与失败恢复。平台服务缺失时给出明确安装说明。
3. 完成数据备份与恢复说明；验证旧版本作品可读、新字段有默认值、更新不会覆盖个人作品。
4. 确认每个人的密钥、平台账号、作品目录独立；仓库和分发包都不含作者的运行数据。当前仅允许本机使用，公网多人部署另列项目。
5. 选定可复用的画风、角色和动作示例，明确实际效果与限制，说明第三方素材和模型的使用条件。
6. 明确源码运行或安装包二选一的首批交付方式；安装包还需要独立构建、签名和干净设备验证，目前不承诺可直接双击安装。

上述条件完成后再邀请约3–5位朋友试用。每位先完成一篇2–4格作品，不预置作者账号，不收集密钥或Cookie。

## 阶段三：小范围反馈与迭代

每次反馈记录：版本/系统、所在步骤、期望结果、实际结果、是否影响继续操作、可选截图、模型类型与耗时。不要粘贴密钥、验证码或完整登录日志。

优先顺序：数据丢失与安全问题 → 阻塞主流程 → 角色/动作错误 → 排版与窄屏易用性 → 便利功能。修改记录继续保留“原效果、怎么改、为什么改、验证结果”。

## 后续候选，不在当前版本承诺范围

- 本地画质：进一步研究适用的画风 LoRA、姿态/结构控制、可复现参数与局部修图；按16GB设备的资源限制逐项评估。
- 连载：角色设定版本、关系与道具连续性，以及多角色参考能力的实际验收。
- 素材：平台关键词搜索、正文/字幕读取成功率和来源去重；登录失效的恢复体验。
- 分析：可获得的发布指标自动采集、统一观察窗口、图表和关键词方向反馈；缺失数据不填成0。
- 发布：按平台的标题、字数、标签与标识要求做适配，先保留人工确认发布。
- 协作或公网版：先设计身份认证、用户隔离、文件访问、额度和任务队列，再决定是否实施；不直接把当前本机端口暴露给朋友。

## 发布门槛

作者完成主路径验收；干净设备能独立运行；严重阻塞项清零；已知限制清楚；能备份恢复；密钥和登录状态不随包分发。届时记录版本与变更日志，并保留回退版本。
