# 平台采集修复 · 2026-11-06

## 复现与原因

- 抖音已存在本机会话。通过实际 `/api/comicStudio/platformSession` 搜索返回 422「没有标题与标准链接」。窗口预览证实搜索页被滑块验证码遮挡；原检测只看同源正文前 2000 字，遗漏跨域验证窗口。
- 小红书 `/api/comicStudio/xhsLogin?action=status` 返回未登录，搜索仍等待上游并报通用 500。Cookie 文件存在不代表平台仍认可登录。
- 上游 xiaohongshu-mcp 每次请求新二维码会关闭之前的待扫码会话，原应用只在单个前端页面避免重复，无法覆盖多窗口或刷新。

## 修改

- 抖音识别可见验证 iframe 和验证提示；等待标准视频、图文与 modal_id 链接。同一搜索 URL 重试不再次导航，用户完成验证后可直接采集原页。
- 已保存的专用浏览器资料在后端重启后可按采集请求恢复；Windows Chrome 支持用户级和系统级安装路径。
- 小红书搜索、正文及互动数读取前先确认会话。失效返回 409 并引导设置重新登录，前端同步清除过时的「已连接」状态。
- 服务端复用有效二维码，返回实际剩余秒数；启动服务明确设置本机 Cookie 文件位置，Windows 使用 exe 服务入口。平台自身失效或验证码仍需本人处理，不承诺永久登录。
- 论坛公开搜索为空或失败时尝试本人浏览器，并显示实际浏览器失败原因，不再掩盖为原来的公开源 403。

## 实际验证与边界

- 本机实际请求验证：小红书失效搜索返回 409 和明确重新登录提示；重复二维码请求图像一致、剩余时间递减。
- 抖音原页因本人滑块验证尚未完成，登录后的成功采集结果等待本人验证，不把错误提示修复等同于采集成功。
- 小红书重新扫码后的成功搜索待本人确认。未输出 Cookie、密钥或扫码图片到仓库。
- 未调用文本或图片模型。Windows 通过 GitHub 构建测试安装包，不能替代 Windows 真机验收。
